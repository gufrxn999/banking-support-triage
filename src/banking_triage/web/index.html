The policy

One classifier, four honest outcomes

The classifier is a routing signal, not the product. It never writes prose and never overrides the safety policy. Routing lives in one auditable module.

01 Message free text, ≤ 2,000 chars
→
02 Classify TF-IDF + logistic regression
→
03 Decide confidence + margin + policy
→
04 Act & compose FAQ · rate · clarify · handoff
faq auto_answer

Answer from reviewed copy

Fires when confidence ≥ 0.54, the top-1/top-2 margin is ≥ 0.10, and the predicted intent has curated copy. The answer is retrieved, never generated.

source: faq.jsonl · 42 of 77 intents

exchange_rate auto_answer

Quote a dated ECB rate

Fires for the exchange-rate intent with a usable pair, or for an explicit conversion request that names two currencies and an amount. ECB reference rates only — never “today”, never a guess at a missing pair.

source: frankfurter.dev · business-day rates

clarify clarify

Ask instead of guessing

Fires below the confidence floor, on a thin margin, or when a rate question is missing half a pair. Multi-turn state remembers the pending intent, so the next reply can complete the request without re-classifying it.

state: LangGraph checkpointer · in-memory

escalate escalate

Hand off to a person

Fraud and dispute intents never auto-answer, at any confidence. A confident intent without reviewed copy also escalates: improvising policy is worse than a ticket. Tool failures degrade into this path, with the error recorded.

guardrail: NEVER_AUTO_ANSWER_INTENTS

Why not quote the higher number?

The classifier policy can route — of test traffic at — precision — but that counts any confident intent as routable, whether or not a reviewed answer exists. The workflow only answers intents with curated copy, so it resolves —. The difference is a content roadmap with a measurable ceiling, and the report states it instead of hiding it.

Interface

A small, documented API

The page is a client of the same public endpoints. Errors are RFC 9457 problem documents, every response carries a request ID, and a missing model degrades /healthz instead of crashing the process.

POST /triage
curl -s http://127.0.0.1:8000/triage \
  -H 'content-type: application/json' \
  -d '{"text": "convert 250 EUR to CHF"}'
{
  "intent": "fiat_currency_support",
  "confidence": 0.9112,
  "route": "exchange_rate",
  "decision": "auto_answer",
  "route_reason": "explicit_currency_pair",
  "answer": "250.00 EUR = 231.10 CHF at the ECB reference rate …",
  "sources": [{ "kind": "exchange_rate", "ref": "https://api.frankfurter.dev/…" }],
  "needs_human": false,
  "steps": ["triage", "exchange", "compose"],
  "latency_ms": 6.1
}
